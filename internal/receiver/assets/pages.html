Status API guide

Make your first request

Ask your Bridge Health administrator for a read-only token. Store it in your service’s secret store and load it into the BRIDGE_HEALTH_TOKEN environment variable.

curl -fsS -H "Authorization: Bearer ${BRIDGE_HEALTH_TOKEN}" \
  {{.Origin}}/api/v1/status

The response lists each enrolled reporter. The status field summarizes its health. A new reporter can appear before its first heartbeat arrives.

Example response for a new reporter 
{
  "updated": "2026-11-22T15:00:00Z",
  "nodes": [{
    "nodeId": "Example Pillar",
    "streamId": "11111111-2222-4333-8444-555555555555",
    "status": "Awaiting report",
    "access": "active",
    "delivery": "never",
    "created": "2026-11-22T14:55:00Z",
    "certificateExpires": "2027-11-22T14:56:00Z",
    "latest": null
  }]
}

Read status and history

GET /api/v1/status returns updated and nodes. After a successful read, latest.heartbeat.snapshot contains the build, bridge state, sync heights and per-chain wrap and unwrap observations. Check each observation’s quality and asOf before using its value.

GET /api/v1/status/{streamId} returns updated, node and history. Use a streamId from the fleet response. History contains up to 30 earlier receipts, oldest first. When a socket read fails, the snapshot is null and node.historicalSuccess holds the last successful receipt if available.

All timestamps use UTC. The API omits IP addresses and redacts IP literals in pillar names and build labels.

Polling and errors

Reporters usually check in once a minute. Each token allows one request per second on average, with a burst of ten.

401 Unauthorized
Check the bearer header and whether the token has expired or been revoked.
404 Not Found
Look up the stream ID in the fleet response.
429 Too Many Requests
Wait the number of seconds in the Retry-After header before retrying.
500 Internal Server Error
The receiver could not read the retained status. Retry on the next poll.
